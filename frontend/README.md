# EdgeLab frontend

Stripe credentials and provider price IDs stay on the FastAPI server. Public pricing reads the validated server catalog and offers monthly/yearly hosted checkout for verified accounts. Unconfigured, test-mode and provider-error states remain explicit. Choosing a cadence or returning from checkout never grants access or starts another purchase automatically; paid status is checked on the server. The optional beta workspace remains separate, and data exports still require an active paid subscription.

For legacy beta accounts without a Google identity, sign out in Account and verify the exact same email with Google. Gmail and Google Workspace ownership claims can preserve the account's history while revoking older sessions. Third-party email without Google ownership authority needs separate mailbox recovery before an existing account can be linked; this recovery flow is not yet implemented. Existing Google subject sign-in remains supported. A verified identity does not itself grant paid access.

The native Pine foundation pins PineTS 0.11.0 with reviewed local source patches and builds a separate classic worker asset with esbuild. The shared source resolver verifies dependency and patch hashes before either development or production builds; the installed npm package is unchanged. See [engine source notes](vendor/pinets/README.md). The browser fetches that trusted asset from its own origin, then runs compilation and execution in a blob worker created inside an opaque `sandbox="allow-scripts"` frame. Its CSP denies network connections, imports and parent-origin storage; user source and results travel only as messages. The parent verifies frame identity, a cryptographic nonce and bounded result schemas, and the fixed bridge terminates/revokes its worker on completion, cancellation or timeout. These are isolation and availability controls, not a global memory/operation budget. Unsupported secondary-symbol/timeframe requests fail explicitly; data comes from the supplied local candle context.

The chart editor supports EdgeLab DSL and native Pine v5/v6. Choose a Pine template or paste source with a version header, then **Check script** to generate declared settings and enable saving. **Run** calculates the loaded chart snapshot; **Add to chart** saves source, inputs and validated metadata together. Script history and chart workspaces preserve native source and inputs. Source, input, context and account changes invalidate pending results. After the build, `npx playwright test --config=e2e/pine-copy55.config.ts` checks genuine custom-input runs and saved chart persistence at three viewport sizes.

Direct field history on registered UDT receivers is rejected with a corrective diagnostic; assigning a field to a scalar before referencing its history remains supported. These follow the [v6 object-history syntax](https://www.tradingview.com/pine-script-docs/migration-guides/to-pine-version-6/#history-of-udt-fields). After building, `npx playwright test --config=e2e/pine-history56.config.ts` checks custom lookback settings, saved-source reload and chart application with the genuine worker on desktop, tablet and mobile. These tests do not establish absent-object field access or complete TradingView equivalence.

Circle joins and trackprice guides retain visible unsupported notices. Areas use the declared color for both their solid fill to `histbase` and their outline, replacing the previous local gradient approximation. Area plots bridge missing values; broken areas retain gaps and exclude the baseline from their plotted-value scale. Histogram widths use the declared constant positive integer in pixels, defaulting to one; widths such as 12 are supported independently of the local 1–4 pixel line-width limit. Columns ignore linewidth and resize with real logical bar slots, using the pinned chart's physical-pixel gap cadence with an explicit calibration notice. Numeric filled plots require constant finite baselines, and histograms require constant widths; invalid or changing settings are omitted with a visible reason. Histogram and column baselines always contribute to scale under the documented model, including empty/offscreen channels; the all-missing TradingView corner case has not been observed. An area baseline contributes when visible numeric or clipped bridge geometry exists; empty-area scale behavior is not calibrated. Packed numeric results remain lazy through pan, zoom, resize and disposal.

Large native results use fixed transferable buffers, with at most 1,280,000 bar slots, 16,000,000 total bytes and 1,000,000 bytes of plain metadata. Values, presence/type flags and deduplicated per-bar options remain packed in the browser; timestamps bind to the requested bars. Changing numeric options use Float64 columns and presence flags within the existing three buffers per output. Constant numeric options remain in the dictionary. Requested samples reconstruct their options lazily, preserving absent, null, zero, string and boolean values. Small results retain plain point arrays only below 4,097 aggregate bar slots. Hidden references, null-valued fills, booleans, sparse points and OHLC values remain distinct. OHLC-heavy results or many numeric option columns can reach the byte limit before the channel limit. Invalid, shared, resizable, aliased or incorrectly sized buffers and invalid fill references fail explicitly. These bounds do not constitute a global memory budget for the Pine engine.

The 64-channel host capacity differs from TradingView’s [64 plot counts](https://www.tradingview.com/pine-script-docs/writing/limitations/#plot-limits), which depend on function arguments and series qualifiers. Exact TradingView count enforcement is not established. SuperTrend, Chandelier Exit and HalfTrend retain their nine original channels, including hidden fill references, dynamic translucent fills and absolute circles, triangles and Buy/Sell shapes with independent text colors. Shape size and font metrics use local pixels; exact TradingView typography calibration remains unverified. Unsupported drawing types remain disclosed rather than changing the preserved source.

Gradient coordinates are clipped to the canvas with sampled endpoint colors, preserving the original ramp when anchors lie far offscreen. Missing numeric anchors and two transparent endpoints produce no fill; equal anchors use an empty-render policy, and reversed anchors retain their endpoint identities. Exact TradingView corner-case pixels for these local policies are not established. Oversized results fail explicitly rather than pruning output.

## Run it

Install the root workspace dependencies, then start the frontend:

```bash
npm install
npm run dev:frontend
```

Vite listens on <http://127.0.0.1:5173> and proxies `/api` to FastAPI on port 8000. For the complete local development stack, use `npm run dev` from the repository root.

A fresh Vite development preview on `localhost`, `127.0.0.1`, or `[::1]` shows the redesigned interface even when FastAPI is offline. Saved rollout policy and subsequent server responses take precedence; malformed or expired stored policy keeps the compatibility fallback. Production builds still wait for valid server policy. This presentation fallback does not bypass sign-in, subscription checks, or API requirements for workspace data.

Chart toolbar, study settings, and replay controls wrap at narrow widths while retaining touch-sized actions. The dedicated `e2e/pine-study-geometry51.config.ts` suite checks 320px, 390px, tablet and desktop geometry through genuine Pine execution, input edits, keyboard focus, visibility changes and removal against an already-built frontend. It uses explicit session and subscription fixtures rather than live billing.

The landing page has one interactive chart/journal/results preview. Its clearly labelled synthetic market generates continuous OHLCV history, retains 2,048 bars, and fits a dense past-only window to the chart width. Pause, stepping, scrubbing and chart gestures allow inspection; Play returns to the newest candle. Automatic generation pauses offscreen, in hidden tabs and with reduced motion. The larger 3D study uses a fixed synthetic session so its decision chapters preserve context. Text and component transitions use finite scroll-triggered tweens rather than scroll-scrubbed partial poses. `e2e/landing-continuity52.config.ts` checks actual chart continuity, responsive density, motion completion, reduced motion, WebGL framing and current-product copy.

## Indicator calculations

The library includes native chart studies and 20 first-party EdgeLab DSL studies. Native and DSL ATR/RSI use Wilder smoothing with a full-period seed; ADX waits for both directional-movement and DX warmup windows. SuperTrend retains recursive trailing bands and changes direction on closing-price crossings. Flat RSI and MFI return a neutral 50; unchanged typical prices contribute to neither side of MFI.

Historical Volatility requires a complete window of valid positive-price log returns. Its `periodsPerYear` input defaults to 252 and should be set to the expected number of bars per year for the chart timeframe and market calendar. Existing two-argument `histvol(source, period)` scripts retain the 252 default; `histvol(source, period, periodsPerYear)` supports explicit annualization.

Chart VWAP follows the pane's selected exchange session, including FX/CME overnight rollover and daylight saving time. It accumulates the filtered source bars before chart aggregation, then plots the last VWAP value in each chart candle; a candle spanning rollover therefore uses the current session's source volume. Calculations without a session context retain the UTC-day default.

Custom studies use a 350 ms worker limit on Live charts and a 1,200 ms limit on Replay charts. Cancellation and every completion/error path clear timers and terminate the worker; a browser worker-start failure is shown as an indicator error.

ATR and SuperTrend follow the published [ATR smoothing](https://www.tradingview.com/support/solutions/43000501823-average-true-range-atr/) and [SuperTrend band recurrence](https://www.tradingview.com/support/solutions/43000634738-supertrend/) definitions. EdgeLab's original indicator DSL is separate from the native Pine execution path.

Native Pine strategies expose **Strategy test settings** after Check: starting capital, default size (units, cash or percent of equity), commission, integer slippage ticks, same-direction entry limit and market-order close timing. Blank fields retain source defaults; clearing one field removes only that override, and **Use script defaults** removes all overrides. Values are validated before execution, and the worker response must preserve every requested setting. Saving stores the assumptions beside the unchanged source; duplication, version history, saved-library reload, chart instances and Quant strategy tests retain them. Chart settings can change the assumptions for one instance without rewriting the saved library. Explicit order quantities override default size; pyramiding applies to entry orders, and close timing does not enable additional calculations. Cash and capital use the strategy's account currency; exchange-rate conversion is unavailable. The controls use host bounds (positive capital/size; nonnegative fees; whole slippage ticks up to 10,000 and entry limit up to 1,000), not a claim of TradingView limits. Invalid saved assumptions reject the affected script rather than silently changing its test.

Editor runs, Replay and Live providers without authoritative candle-close events execute closed historical snapshots. The primary Binance Live chart exposes the same editor and saved library, with one persistent opaque sandbox worker per visible native indicator. Closed history initializes once; received one-minute kline events update the forming chart bucket in order, roll back ordinary state, preserve supported `varip` state and replace provisional outputs. A higher-timeframe candle closes only when its final constituent minute explicitly closes. These are Binance sampled kline events, not every raw trade. Duplicate committed closes are ignored; gaps, revisions of committed bars, queue overflow, deadlines and malformed messages halt the affected session rather than inventing closes or silently dropping updates. The host queue holds at most 32 commands, history at most 20,000 bars, initialization at most ten seconds and each update at most two seconds. Inputs and source changes restart only that study; hiding, removing, changing chart context/account or leaving Live cancels its worker. Other normalized panes, strategies, unprepared scripts and charts with session filtering or a non-24x7 session retain closed snapshots. Live strategy scheduling remains unavailable. After building, `npx playwright test --config=e2e/pine-live58.config.ts` verifies the genuine persistent bridge and actual Live editor at three viewport sizes. This is qualified experimental execution, not complete TradingView equivalence. Historical strategy runs accept and preserve resolved true or false `calc_on_every_tick` declarations: this setting affects open realtime bars, so closed historical bars still calculate once per bar. This does not enable live strategy tick scheduling. Historical runs also accept resolved boolean `calc_on_order_fills`: actual order fills trigger recalculation along an assumed open → nearer extreme → farther extreme → close price path. Historical callbacks retain the final OHLCV values and commit one output/history slot per candle; ordinary script state rolls back between callbacks, while the broker ledger and supported `varip` state persist. New orders cannot revisit a passed price segment. This model can produce optimistic results compared with actual trades. `calc_on_every_history_tick=true` still fails with `UNSUPPORTED_EXECUTION_SETTING` before the script body. Custom-quantity persistent exits covering later entries and intrabar margin-liquidation simulations with fill recalculation fail explicitly with `UNSUPPORTED_ORDER_FILL_CONTEXT`; lower-timeframe bar magnification is unavailable. Fill execution stops after 512 calculations or 2,048 broker transitions per candle with `STRATEGY_EXECUTION_LIMIT`. The bounded rollback graph retains the existing limits described above; those bounds do not establish a total heap limit.
