# EdgeLab frontend

The native Pine foundation pins PineTS 0.11.0 and builds a separate classic worker asset with esbuild. The browser fetches that trusted asset from its own origin, then runs compilation and execution in a blob worker created inside an opaque `sandbox="allow-scripts"` frame. Its CSP denies network connections, imports and parent-origin storage; user source and results travel only as messages. The parent verifies frame identity, a cryptographic nonce and bounded result schemas, and the fixed bridge terminates/revokes its worker on completion, cancellation or timeout. These are isolation and availability controls, not a global memory/operation budget. Unsupported secondary-symbol/timeframe requests fail explicitly; data comes from the supplied local candle context.

The chart editor supports EdgeLab DSL and native Pine v5/v6. Choose a Pine template or paste source with a version header, then **Check script** to generate declared settings and enable saving. **Run** calculates the loaded chart snapshot; **Add to chart** saves source, inputs and validated metadata together. Script history and chart workspaces preserve native source and inputs. Source, input, context and account changes invalidate pending results.

Chart Objects provides an explicit Settings disclosure for each indicator, separate from its On/Off visibility action. Native Pine settings use the same validated, exact-source input definitions as the chart toolbar and trigger genuine snapshot recalculation; generic color/period fields are reserved for other study types. The caption distinguishes Pine source version from saved revision. Hidden studies remain configurable, Close and Escape return to the disclosure trigger, and removing a focused study moves focus to a surviving control in the same panel. Replay shortcuts respect handled key events and let focused interactive controls receive Space instead of toggling playback. Main and native-pane charts use the public [visible-range resize lock](https://tradingview.github.io/lightweight-charts/docs/4.2/api/interfaces/TimeScaleOptions#lockvisibletimerangeonresize), preserving their established time context as panel width changes within the chart library's spacing limits. This does not establish exact TradingView pane alignment or behavior beyond those limits.

The Active studies strip exposes native Pine inputs through a per-study Inputs disclosure rather than generic Len and Study color controls. It uses the saved script's validated input definitions and current custom values, so edits here and in Objects configure the same study and rerun the native snapshot. Source version and saved revision remain distinct, and scripts without configurable inputs or valid prepared metadata show the appropriate explanation. Inputs are contained for long lists, and Close/Escape returns focus to the opening control.

Native Pine uses the active symbol’s session-filtered, aggregated chart bars, up to the latest 20,000 loaded bars. Live chart calculations exclude the forming timeframe bucket. Common line, step, area, histogram, candle and circle plots preserve placement, colors and null gaps. Scalar lines, areas, histograms, columns, referenced fills and supported shapes share a canvas primitive per chart placement; disconnected histories no longer create a series per segment or stop after sixteen segments. Unsupported drawings/styles/options still produce visible warnings. The runtime permits 64 native output channels and 24 inputs. Secondary-symbol/timeframe data requests fail instead of fabricating candles.

Constant integer `plot()` offsets move line, broken-line, step-line, circle, area, broken-area, histogram and column geometry through actual chart bar slots, including visible past/future whitespace. This follows the [Pine visual offset model](https://www.tradingview.com/pine-script-docs/visuals/plots/): source values, timestamps, colors and header values remain unchanged; `show_last` filters source bars before their visual shift. Sparse chart timelines retain their real logical spacing, and autoscale uses clipped shifted geometry rather than offscreen endpoint prices. Positional and named plot settings retain custom inputs and flags after `join`; explicit `force_overlay=false` retains the script's own overlay placement. Invalid or changing offsets fail explicitly. These guards check resolved historical values, not Pine's complete type-qualifier rules. The pinned runtime's 15 plot arguments are supported; the newer `linestyle` argument fails explicitly. Circle joins and trackprice guides retain visible unsupported notices. Offsets for candles, shapes and fill references remain visibly unsupported; exact TradingView pixels and realtime execution parity are not established.

Areas use the declared color for both their solid fill to `histbase` and their outline, replacing the previous local gradient approximation. Area plots bridge missing values; broken areas retain gaps and exclude the baseline from their plotted-value scale. Histogram widths use the declared constant positive integer in pixels, defaulting to one; widths such as 12 are supported independently of the local 1–4 pixel line-width limit. Columns ignore linewidth and resize with real logical bar slots, using the pinned chart's physical-pixel gap cadence with an explicit calibration notice. Numeric filled plots require constant finite baselines, and histograms require constant widths; invalid or changing settings are omitted with a visible reason. Histogram and column baselines always contribute to scale under the documented model, including empty/offscreen channels; the all-missing TradingView corner case has not been observed. An area baseline contributes when visible numeric or clipped bridge geometry exists; empty-area scale behavior is not calibrated. Packed numeric results remain lazy through pan, zoom, resize and disposal.

Large native results use fixed transferable buffers, with at most 1,280,000 bar slots, 16,000,000 total bytes and 1,000,000 bytes of plain metadata. Values, presence/type flags and deduplicated per-bar options remain packed in the browser; timestamps bind to the requested bars. Changing numeric options use Float64 columns and presence flags within the existing three buffers per output. Constant numeric options remain in the dictionary. Requested samples reconstruct their options lazily, preserving absent, null, zero, string and boolean values. Small results retain plain point arrays only below 4,097 aggregate bar slots. Hidden references, null-valued fills, booleans, sparse points and OHLC values remain distinct. OHLC-heavy results or many numeric option columns can reach the byte limit before the channel limit. Invalid, shared, resizable, aliased or incorrectly sized buffers and invalid fill references fail explicitly. These bounds do not constitute a global memory budget for the Pine engine.

The 64-channel host capacity differs from TradingView’s [64 plot counts](https://www.tradingview.com/pine-script-docs/writing/limitations/#plot-limits), which depend on function arguments and series qualifiers. Exact TradingView count enforcement is not established. SuperTrend, Chandelier Exit and HalfTrend retain their nine original channels, including hidden fill references, dynamic translucent fills and absolute circles, triangles and Buy/Sell shapes with independent text colors. Shape size and font metrics use local pixels; exact TradingView typography calibration remains unverified. Unsupported drawing types remain disclosed rather than changing the preserved source.

Native vertical gradient fills use referenced plots or horizontal lines as their mask, while independent `top_value`/`bottom_value` and endpoint colors control the ramp, following the [documented Pine gradient model](https://www.tradingview.com/blog/en/pine-script-vertical-gradients-33586/). Series values, endpoint colors and alpha remain attached to their original bars. Hidden references and gradient anchor values do not expand an established price scale. Gradient coordinates are clipped to the canvas with sampled endpoint colors, preserving the original ramp when anchors lie far offscreen. A per-instance compatibility wrapper retains resolved gradient title, display, fillgaps and editable settings that PineTS 0.11.0 drops; editable is preserved metadata rather than a separate fill-style editor. `show_last` belongs to the solid-fill overload and is rejected for gradients. Missing numeric anchors and two transparent endpoints produce no fill; equal anchors use an empty-render policy, and reversed anchors retain their endpoint identities. Exact TradingView corner-case pixels for these local policies are not established. Continuously changing numeric gradient anchors remain packed through 20,000 bars without one dictionary entry per bar. The existing metadata and total byte limits still apply: changing string colors or text can enlarge the dictionary, and numeric columns consume the binary budget. Oversized results fail explicitly rather than pruning output.

The same scoped fill wrapper recognizes positional solid fills with an `na` color and preserves their title, editable, show_last, fillgaps and display settings instead of misclassifying them as gradients.

Native `bgcolor()` paints per-bar shading behind fills and price plots, preserving sampled colors and transparency without numeric headers or scale expansion. Constant integer offsets, `show_last`, `display`, editable metadata and main-chart placement are retained through positional or named arguments. The scoped runtime wrapper gives global background calls separate host identities and preserves invocation order, including duplicate or numeric titles; `force_overlay=false` retains the script's own overlay placement. Changing non-color options or changing the number of calls across bars fail explicitly. This observed-value validation does not establish complete Pine type-qualifier enforcement. Backgrounds retain packed backing and decode only visible shifted bars. Half-bar boundaries and canvas alpha rasterization use local chart geometry; exact TradingView pixel parity and declaration `behind_chart=false` placement remain unverified. The live [v6 reference](https://www.tradingview.com/pine-script-reference/v6/#fun_bgcolor) includes `display` before `force_overlay`, although the conceptual backgrounds page currently omits it.

Native `barcolor()` changes the main candle bodies, including when the indicator runs in a separate pane, following the [documented body-color behavior](https://www.tradingview.com/pine-script-docs/visuals/overview/#background-and-bar-coloring). Wick and border settings, hidden bodies, OHLC values and timestamps stay intact. Named and positional color, offset, editable, show_last, title and display arguments retain custom inputs; `na` leaves a bar unchanged, while an alpha-zero color makes its body transparent. Source-first `show_last` and constant integer offsets map to real displayed bar slots; future slots without an existing candle do not create fabricated bars. Bar coloring adds no numeric series, price scale or header value. Candle and Heikin Ashi charts display it; line, area, footprint and TPO charts disclose that coloring is unavailable. Hiding, removing, recalculating or invalidating a study restores chart defaults without moving a manually panned view when the chart layout is unchanged. Later non-missing calls and later active studies in chart order take precedence under a local deterministic policy; exact TradingView multi-study precedence is unverified. Non-color flags and global call counts must remain constant across the snapshot, with explicit rejection of invalid or changing settings. These resolved-value guards do not establish full Pine qualifier enforcement. Packed colors are looked up on demand without expanding or retaining the native history as point objects; editable remains metadata rather than a separate color-style editor.

Native `hline()` outputs render fixed horizontal levels across the full pane with solid, dashed or dotted styles, following the [documented levels model](https://www.tradingview.com/pine-script-docs/visuals/levels/). Declared prices, colors, widths, titles, display and editable metadata survive native execution and custom-input save/reload. Visible levels contribute to the price range; hidden levels, missing prices and transparent colors do not paint or expand it. A newer real price-chart endpoint keeps the shared renderer's coordinates and autoscale available when the chart timeline advances past a Pine snapshot. It does not add invented timestamps or native samples. Levels retain packed historical backing and do not decode every bar during drawing. Omitted colors/styles use qualified local defaults; the width defaults to one pixel. Dash/dot spacing uses local pixel metrics, and exact TradingView pixel calibration remains unverified. Changing per-bar level prices/settings and unknown styles are omitted with a reason; this is observed-value validation rather than complete Pine type-qualifier enforcement. Editable remains metadata, not a new style dialog. Fills between horizontal-line references retain their historical sampled geometry; extension of those fills through future whitespace remains unverified.

Grouped canvas channels retain packed backing and decode viewport samples with the neighboring values needed at its edges. Range summaries and numeric indices bound repeated scrolling work. Hidden references do not draw or expand an established visible plot range; a fill-only pane derives its fallback coordinates from currently colored fill geometry, while a fill-only overlay uses the existing price chart scale. Multiline shape text retains its layout and paints the lines within the viewport. Chart owners dispose the renderer and its range subscription before removing the chart. Scripts with more than four visible outputs keep settings accessible beside a collapsible, scrollable list of every output and value; pane captions also collapse above eight outputs.

Pine strategies use their own entries, exits, capital and cost settings. The editor and Quant show the actual engine metrics, closed trades, open positions and pending orders; open positions are not forcibly closed and pending orders are not counted as fills. Quant’s DSL crossing rules do not apply to native scripts. PineTS is experimental and strategy results must not be presented as TradingView-identical. Snapshot execution uses UTC, a 24x7 session and USD, and missing tick/point metadata falls back to 0.01/1 with warnings. Compare assumptions before relying on results.

Pine-enabled builds use AGPL-3.0-only: distribute the complete matching application source and build scripts, and offer them to service users. `LICENSE.txt` and `THIRD_PARTY_NOTICES.txt` ship as static assets and are linked from the native editor; these notices are not a substitute for matching application source. See the root notices for upstream attribution.

## Run it

Install the root workspace dependencies, then start the frontend:

```bash
npm install
npm run dev:frontend
```

Vite listens on <http://127.0.0.1:5173> and proxies `/api` to FastAPI on port 8000. For the complete local development stack, use `npm run dev` from the repository root.

## Indicator calculations

The library includes native chart studies and 20 first-party EdgeLab DSL studies. Native and DSL ATR/RSI use Wilder smoothing with a full-period seed; ADX waits for both directional-movement and DX warmup windows. SuperTrend retains recursive trailing bands and changes direction on closing-price crossings. Flat RSI and MFI return a neutral 50; unchanged typical prices contribute to neither side of MFI.

Historical Volatility requires a complete window of valid positive-price log returns. Its `periodsPerYear` input defaults to 252 and should be set to the expected number of bars per year for the chart timeframe and market calendar. Existing two-argument `histvol(source, period)` scripts retain the 252 default; `histvol(source, period, periodsPerYear)` supports explicit annualization.

Chart VWAP follows the pane's selected exchange session, including FX/CME overnight rollover and daylight saving time. It accumulates the filtered source bars before chart aggregation, then plots the last VWAP value in each chart candle; a candle spanning rollover therefore uses the current session's source volume. Calculations without a session context retain the UTC-day default.

Custom studies use a 350 ms worker limit on Live charts and a 1,200 ms limit on Replay charts. Cancellation and every completion/error path clear timers and terminate the worker; a browser worker-start failure is shown as an indicator error.

ATR and SuperTrend follow the published [ATR smoothing](https://www.tradingview.com/support/solutions/43000501823-average-true-range-atr/) and [SuperTrend band recurrence](https://www.tradingview.com/support/solutions/43000634738-supertrend/) definitions. EdgeLab's original indicator DSL is separate from the native Pine execution path.

Native Pine execution treats supplied bars as closed historical snapshots, including Live chart snapshots. Bar states derive from their position in that snapshot rather than wall-clock time; the final bar is confirmed historical data. Tick updates, realtime rollback and `varip` persistence between ticks remain unavailable. Preparation discloses these boundaries. Enabled `calc_on_every_tick`, `calc_on_order_fills` and `calc_on_every_history_tick` strategy settings fail with `UNSUPPORTED_EXECUTION_SETTING` after resolving their values, rather than silently running once per bar. False constant and input aliases retain normal next-bar order processing. These compatibility guards are scoped to each isolated PineTS 0.11.0 instance; they do not rewrite user source or modify global engine prototypes.
