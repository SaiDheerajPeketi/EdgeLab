# Frontend feature and compatibility reference

This reference retains the detailed implemented behavior, formula caveats and regression pointers previously accumulated in the frontend README. Start with the [frontend development guide](../frontend/README.md) and [architecture](architecture.md). Use source/tests to resolve conflicts; measurements and numbered iteration notes describe their recorded cases, not universal TradingView parity. Keep new setup/operating instructions in their canonical guide rather than appending release notes here.

## Feature and compatibility details

Google sign-in uses the official Better Auth client when the API reports `auth_provider=better-auth`. The client requests the Google authorization-code redirect with automatic redirect disabled, checks the still-owned account and latest fresh attempt, and opens only Google's HTTPS authorization host. The native service callback is `/api/better-auth/callback/google`; its validated return enters the existing one-use frontend callback and bridges the signed cookie through `/api/auth/better-auth/exchange`. The original account identity is retained in the local attempt, so a changed account cannot inherit an old sign-in destination. Tokens and shared destinations never enter the Google callback URL.

Vite proxies `/api/better-auth` to loopback port 3002 and other API paths to 8000. Nginx uses the same public prefix in deployment. Better Auth is unavailable without its Google credentials; the frontend does not hide a failed Better Auth flow behind legacy sign-in. Local beta developer sign-in remains separate and cannot grant paid exports. See [backend configuration](../backend/README.md#authentication-and-access).

The **Indicators** library adds full Stochastic %K/%D, Stochastic RSI, Directional Movement Index (+DI, −DI, ADX), Parabolic SAR, and Ichimoku Cloud directly to the chart. Search a name, choose **Add**, then adjust its inputs in the study settings. Favorite quick-add uses the same isolated Pine preparation. A pending add is retired when its chart or account context changes; adding a built-in does not save a user script. The library retains the existing raw Stochastic %K and standalone ADX studies separately.

The indicator editor's **New script… → Pine indicators** menu opens ten original editable EdgeLab starters: these five plus MACD, Bollinger Bands, Donchian Channel, UTC Daily VWAP, and Heikin-Ashi Candles. Choose a starter, check it with **Run**, then **Save** or **Add to chart** with custom inputs. Choosing a starter opens an unsaved draft; saved scripts and community source archives stay separate. These are original implementations of familiar formulas, not redistributed TradingView built-in source. Stochastic defaults to 14/3/3; Stochastic RSI uses RSI 14, lookback 14, and 3/3 smoothing on a 0–100 scale, with configurable 80/20 levels. DMI uses independent 14-period DI and ADX smoothing; SAR uses 0.02/0.02/0.2 acceleration settings. The formulas follow TradingView's descriptions of [Stochastic](https://www.tradingview.com/support/solutions/43000502332-stochastic-stoch/), [Stochastic RSI](https://www.tradingview.com/support/solutions/43000502333-stochastic-rsi-stoch-rsi/), [DMI](https://www.tradingview.com/support/solutions/43000502250-directional-movement-dmi/), and [SAR](https://www.tradingview.com/support/solutions/43000502597-parabolic-sar-sar/); native warmup and flat-range handling remain independently tested engine behavior, not a claim of complete TradingView calibration. Ichimoku's displacement counts the current bar (26 means an offset of 25); UTC VWAP uses only loaded chart bars and starts afresh each UTC day.

Native Pine `ticker.heikinashi()` requests use independently calculated OHLC after aggregating owned standard candles to the requested timeframe. Standard and transformed execution contexts stay separate; lower-timeframe arrays share the full transformed history, and received live replacements recalculate the forming bar. The first loaded open uses `(open + close) / 2`, so older TradingView history can produce different opens. Strategy orders still fill against standard chart prices. Session/adjustment feeds and other nonstandard chart transforms remain unavailable.

The landing and pricing pages use launch content and **View plans** actions by default, including on a locally configured beta runtime. Open `/?variant=beta` or `/pricing?variant=beta` for the retained beta presentation; any other variant uses launch content. Public home/pricing navigation and pricing sign-in returns retain this variant, selected cadence, and sanitized attribution. Beta admission actions and seat counts require the API to report an available beta program; a production or unavailable API shows Pro plans instead. This selects marketing copy and navigation only. Sign-in, checkout, workspace access, and export eligibility continue to use the configured deployment mode and server checks. The footer's **Pause page movement / Resume page movement** control also stops the continuous illustrative chart and scene animation. After building, `npx playwright test --config=e2e/marketing-variant157.config.ts` checks both public presentations and actual admission/billing boundaries on desktop and mobile.

Stripe credentials and provider price IDs stay on the FastAPI server. Public pricing reads the validated server catalog and offers monthly/yearly hosted checkout for verified accounts. Unconfigured, test-mode and provider-error states remain explicit. Choosing a cadence or returning from checkout never grants access or starts another purchase automatically; paid status is checked on the server. The optional beta workspace remains separate, and data exports still require an active paid subscription.

Beta checkout requires current approved workspace access within the seat cap. The server checks eligibility before provider work and again after persisting the checkout attempt. Verified production buyers can start their first subscription, and billing status and account management remain available after workspace access is lost.

For legacy beta accounts without a Google identity, sign out in Account and verify the exact same email with Google. Gmail and Google Workspace ownership claims can preserve the account's history while revoking older sessions. Third-party email without Google ownership authority needs separate mailbox recovery before an existing account can be linked; this recovery flow is not yet implemented. Existing Google subject sign-in remains supported. A verified identity does not itself grant paid access.

Google callbacks consume fresh state once. Only a mounted callback can share its pending exchange across React's development effect replay; settled responses and consumed callbacks cannot restore a session on a later visit. Account or token changes and clearing authentication storage invalidate the attempt permanently, including cross-tab changes and transitions back to the original identity. Session writes and every destination handoff retain that ownership and the 15-minute state deadline. Cancellation or expiry with an existing account returns to Account without carrying the old workspace, billing or shared-link destination. After building, `rtk proxy npx playwright test --config=e2e/auth-callback141.config.ts` checks the actual production callback and router with controlled provider responses; it does not verify Google itself.

The native Pine foundation pins PineTS 0.11.0 with reviewed local source patches and builds a separate classic worker asset with esbuild. The shared source resolver verifies dependency and patch hashes before either development or production builds; the installed npm package is unchanged. See [engine source notes](../frontend/vendor/pinets/README.md). The browser fetches that trusted asset from its own origin, then runs compilation and execution in a blob worker created inside an opaque `sandbox="allow-scripts"` frame. Its CSP denies network connections, imports and parent-origin storage; user source and results travel only as messages. The parent verifies frame identity, a cryptographic nonce and bounded result schemas, and the fixed bridge terminates/revokes its worker on completion, cancellation or timeout. These are isolation and availability controls, not a global memory/operation budget. Unsupported secondary contexts fail explicitly; data comes from the supplied local candles, including actual owned intrabar source candles and complete higher-timeframe aggregates.

The chart editor supports EdgeLab DSL and native Pine v5/v6. Choose a Pine template or paste source with a version header, then **Check script** to generate declared settings and enable saving. **Run** calculates the loaded chart snapshot; **Add to chart** saves source, inputs and validated metadata together. Script history and chart workspaces preserve native source and inputs. Source, input, context and account changes invalidate pending results. Native UDT member and type-factory copying use current declared field values, with independent scalar fields and shared references to collections or other objects. See [Pine's shallow-copy contract](https://www.tradingview.com/pine-script-docs/language/objects/#copying-objects). After the build, `npx playwright test --config=e2e/pine-copy55.config.ts` checks genuine custom-input runs and saved chart persistence at three viewport sizes.

Live Binance panes load up to 1,000 native provider candles for supported intervals through calendar months. Each pane owns its canonical symbol, actual source interval and Pine metadata, even when another market is selected in the watchlist. The existing primary minute feed is retained; secondary minute panes receive independent native history and updates. The live chart symbol chooser uses trading crypto pairs from the existing Binance catalog and preserves provider identity. Other exchange prefixes remain outside Binance routing, and journal-focused panes retain normalized historical data and their own review range. Drawings are retained per pane and provider-qualified market: switching symbols hides foreign price drawings, restores the destination market's saved drawings, and resets the active drawing undo history. Legacy layout drawings stay associated with their saved market. Hourly and daily indicators use interval history instead of a short aggregation of the minute feed. Custom intervals use the largest compatible native source, such as hourly candles for a three-hour chart, with backward pagination bounded at 1,000 candles per request and 16,000 retained source candles. An incomplete leading aggregate is omitted consistently from the chart, editor and live Pine history; the developing tail retains its actual constituents. Compatible visible intervals for the same symbol share their source feed. A larger history requirement restarts only that source, while reducing the requirement preserves it. Account/source changes retire obsolete requests and sockets, and retired histories are released. Provider events preserve full OHLCV, ordered explicit closes and calendar boundaries, and late history cannot replace an authoritative live tail. Actual depth depends on the provider's available history and the source cap; unavailable lower-timeframe constituents are not invented. Intrabar Pine snapshots currently support fixed intraday intervals, and this does not establish full TradingView parity. After building, `npx playwright test --config=e2e/native-history154.config.ts` checks native intervals, `npx playwright test --config=e2e/custom-history155.config.ts` checks custom history, and `npx playwright test --config=e2e/multi-symbol156.config.ts` checks simultaneous markets and historical focus on desktop and mobile.

Native `chart.left_visible_bar_time` and `chart.right_visible_bar_time` receive the actual primary chart's first and last visible candle opening times, in UNIX milliseconds. Pan, zoom and resize reload only scripts that use these chart inputs across their complete owned calculation history, including historical strategies and secondary historical expressions. Native study panes follow the main chart's window. A window containing no primary candles supplies `na`, rather than inventing future candles or silently using the full history. Persistent live indicators recalculate through their ordered session queue while preserving the current candle's confirmation state; ordinary indicators retain their sessions and plotted series. Viewport work coalesces rapid changes, and obsolete window/account/source/feed results cannot publish. Editor runs without a chart viewport retain the whole-snapshot policy. This implements the covered [visible chart-input behavior](https://www.tradingview.com/pine-script-docs/language/type-system/#input), within the existing history and execution limits; it does not establish full TradingView parity. After building, `rtk proxy npx playwright test --config=e2e/pine-viewport140.config.ts` exercises actual chart interactions and worker execution.

Native `input.price` and `input.time` expose horizontal/vertical chart handles, including an atomic point when exactly one of each shares a nonempty inline row and group. Pairing counts all declarations on the row; a third input prevents pairing. Both members must be active. Pointer and keyboard changes preview locally until release or Enter, then rerun the same study with its updated custom inputs; Escape cancels. The selected visible study owns its handles, which use the actual main or study scale, including zero/negative prices and logarithmic/inverted transforms. Chart selection uses only loaded candle times, never fabricated future slots. UTC date/time fields preserve integer UNIX milliseconds and commit valid drafts on blur or Enter.

Input handles stay behind floating settings controls. **Move inputs on chart** closes the controls while keeping the study selected and focuses its first visible handle, allowing direct pointer or keyboard edits across the full plot. Clicking the study title opens its controls again.

Completing a pointer gesture cannot activate controls that appear beneath that same tap. The transient capture guard suppresses its matching compatibility click, clears on a new pointer or key action, and expires after 750 ms; a separate Add action remains available immediately.

Active `confirm=true` inputs open a draft confirmation before **Add to chart** saves or applies the script. **Pick on chart** temporarily releases the editor modal and selects confirmed main-chart anchors in declaration order. Cancelling even after a partial selection preserves the pre-selection draft; **Add with these inputs** is the explicit save/apply step. Separate-pane prices require numeric entry before the first add, because the study has not established a price scale; after adding, their handles use that pane. A script with no available study pane, or a table-only pane without a price scale, retains editable numeric fields without offering an unusable price picker. The editor's explicit **Run** action still tests its current inputs. After building, `rtk proxy npx playwright test --config=e2e/pine-input-anchors134.config.ts` checks the actual app confirmation, persistence and native-worker recalculation, alongside isolated real chart/component scale and lifecycle checks on desktop and mobile.

Pine on the owned primary Binance spot chart reads the selected instrument's `PRICE_FILTER.tickSize` and separate `LOT_SIZE.minQty` and `stepSize`. The editor, snapshot strategies and live indicators retain that provider/account/feed ownership. `syminfo.mincontract` reflects the minimum, while broker quantities use the separate increment; quote/base currency and spot point value are supplied alongside the tick. Orders below the minimum are skipped, and accepted quantities are floored to the increment, including non-power-of-ten steps such as 0.025. Unsupported quantity precision beyond ten decimal places and price ticks without a safe integer `minmove`/`pricescale` fail explicitly. Missing, duplicate or malformed catalog details block Pine on that feed instead of silently assuming whole units. Other provider panes and historical journal-focus snapshots retain the explicit default-metadata warning. This simulation does not enforce notional limits, maximum quantity, separate market-order filters, currency conversion or exchange order acceptance. After building, `npx playwright test -c e2e/pine-instrument69.config.ts` checks the real production worker and metadata arriving late, account switches, feed resets and provider mismatch at three widths.


Pine v6 object history uses `(object[offset]).field`, including direct plot arguments, nested fields and typed function returns. Direct field history on registered UDT receivers is rejected with a corrective diagnostic; assigning a field to a scalar before referencing its history remains supported. These follow the [v6 object-history syntax](https://www.tradingview.com/pine-script-docs/migration-guides/to-pine-version-6/#history-of-udt-fields). After building, `npx playwright test --config=e2e/pine-history56.config.ts` checks custom lookback settings, saved-source reload and chart application with the genuine worker on desktop, tablet and mobile. These tests do not establish absent-object field access or complete TradingView equivalence.

Journal and note settings validate the response envelope and every submitted change before publishing storage or clearing drafts. Missing, malformed or mismatched acknowledgments retain drafts for retry; broker labels follow the server’s trimmed-label and blank-to-Manual rules. Saved feedback applies only while the current form matches confirmed values. Retained callbacks from another account cannot start a read or save. Delayed settings loads cannot replace newer confirmed journal or note values. Choosing a newer preference version preserves the existing draft if loading fails, and preserves later field edits—including explicit returns to the old baseline—during a successful load. Preference writes pause during replacement; later cross-tab conflict notices remain visible.

Provider settings select an implemented, currently connectable provider from the returned catalog, preferring a live adapter over the local fixture for an initial selection. A synchronous action ticket serializes creation, refresh, verification, rotation and revocation, including already-open confirmation controls. Once a credential is acknowledged, its value leaves the form and its vault metadata stays visible even if verification or connection creation fails. Retry continues setup with the same saved credential; discarding setup keeps that record available for explicit revocation. Each step retains the starting account/data ownership. Provider dropdowns and surfaces use the app theme tokens.

Chart Objects provides an explicit Settings disclosure for each indicator, separate from its On/Off visibility action. Native Pine settings use the same validated, exact-source input definitions as the chart toolbar and trigger genuine snapshot recalculation; generic color/period fields are reserved for other study types. The caption distinguishes Pine source version from saved revision. Hidden studies remain configurable, Close and Escape return to the disclosure trigger, and removing a focused study moves focus to a surviving control in the same panel. Replay shortcuts respect handled key events and let focused interactive controls receive Space instead of toggling playback. Main and native-pane charts use the public [visible-range resize lock](https://tradingview.github.io/lightweight-charts/docs/4.2/api/interfaces/TimeScaleOptions#lockvisibletimerangeonresize), preserving their established time context as panel width changes within the chart library's spacing limits. This does not establish exact TradingView pane alignment or behavior beyond those limits.

The Active studies strip exposes native Pine inputs through a per-study Inputs disclosure rather than generic Len and Study color controls. It uses the saved script's validated input definitions and current custom values, so edits here and in Objects configure the same study and rerun the native snapshot. Source version and saved revision remain distinct, and scripts without configurable inputs or valid prepared metadata show the appropriate explanation. Inputs are contained for long lists, and Close/Escape returns focus to the opening control.

EdgeLab scripts also expose their declared numeric, source and boolean inputs in Studies. These controls update the same `customInputs` used by the script runtime; numeric limits retain the last applied value while an invalid edit is corrected. Their separate Study color override is preserved. The indicator library and study controls use the app's semantic palette, with 44px touch targets for library actions. After building, `rtk proxy npx playwright test --config=e2e/indicator-theme129.config.ts` checks the actual product library and script-input flow; its contrasting token probe verifies palette inheritance, not a user-selectable light theme.

Native Pine uses the active symbol’s session-filtered, aggregated chart bars, up to the latest 20,000 loaded bars. Closed snapshot calculations exclude the forming timeframe bucket; primary Binance Live Pine studies use the explicit persistent lifecycle described below. Common line, step, area, histogram, candle and circle plots preserve placement, colors and null gaps. Scalar lines, areas, histograms, columns, candle plots, referenced fills and supported shapes share a canvas primitive per chart placement; disconnected histories no longer create a series per segment or stop after sixteen segments. Unsupported drawings/styles/options still produce visible warnings. The runtime permits 64 native output channels and 24 inputs. Historical runs can receive up to 200,000 actual pre-aggregation source candles, clipped to the chart window and replay cursor. `request.security` selects first/last available intrabars, and `request.security_lower_tf` returns chronological primitive arrays or tuple arrays, with empty arrays where source history is absent. Custom inputs, saved source and nested request identities are preserved. Higher-timeframe expressions require complete consecutive actual source groups; partial displayed candles cannot fill missing source history. Additional Binance symbols are acquired by evaluated historical and persistent-live requests as described below. Persistent live indicators support same-symbol fixed UTC intraday requests using the chart’s actual one-minute feed. Requested engines retain independent rollback and intrabar state; higher-timeframe gaps-off values develop with received ticks, gaps-on waits for that requested bucket’s close, and lower-timeframe arrays contain chronological actual children. Realtime scalar lower-timeframe requests select the latest available child for either lookahead policy. Contexts and written expressions must initialize on historical bars. Mutable live cross-context return types fail explicitly; primitive values and primitive tuples are supported. See [engine source notes](../frontend/vendor/pinets/README.md) for derived-timeframe and cross-boundary qualifications. Static dependent requests retain scalar/tuple values calculated in the original chart context, including native input overrides and inner history; outer operations use the sampled target history. Dynamic requests reevaluate supported inner contexts. Nested calls through known top-level functions retain full written-call identities, including across awaited requests. Unsafe shared-state replay dependencies fail explicitly rather than substituting incorrect history. This is verified historical behavior for the documented cases, with explicit errors for unsupported isolation or transport. Both `request.security` and `request.security_lower_tf` check full exchange-qualified identities before native shortcuts. Empty chart aliases and whole-symbol case matches are accepted; different exchanges, bare aliases on qualified charts and unavailable session/adjustment/nonstandard candles fail explicitly. Explicit `ticker.standard` can remove modifiers for a matching standard chart. A rejected request cannot publish plots or strategy results and halts a persistent live session.

Native declarations preserve `behind_chart` through execution and saved metadata. Checking records literal settings; an unresolved declaration alias produces a pending-layer diagnostic and uses a provisional true value until Run resolves it. Overlay visuals default to drawing behind the main price bars; `behind_chart=false` draws them ahead of the bars, while keeping the chart crosshair above them. Separate-pane outputs retain their placement. Outputs with `force_overlay=true` use the front main-chart layer, following the [declaration precedence](https://www.tradingview.com/pine-script-docs/language/declaration-statements/); fills between two forced references follow those references. `barcolor()` still changes the primary candle bodies. Older saved metadata without this field defaults to true. Invalid or changing resolved declaration values fail explicitly; full Pine constant-qualifier enforcement, exact TradingView corner-case pixels and cross-study stacking parity remain unverified. EdgeLab reruns the snapshot when source is edited; it does not reproduce TradingView’s instance-only application of visual declaration settings.

Native `table.*` drawings use a strict final cell snapshot and an owned HTML layer attached to an empty, non-scaling chart series. Nine fixed positions, separate table-only panes, forced main-chart placement, merged-origin styling, sparse cells, multiline text and passive hover tooltips follow the [table API](https://www.tradingview.com/pine-script-docs/visuals/tables/). Positive cell dimensions are percentages of the pane and can exceed 100%; content clips at the pane edge. Numeric/preset font sizes use typographic points, with a local 14-point `size.auto` default. Otherwise-empty merged axes distribute measured text size locally. Tables draw above chart drawings; exact `behind_chart` and font/pixel calibration, and TradingView's bottom-panel table view, are not supplied. Allocation is bounded before cell creation to nine active tables and 4,096 total cells; percentages are finite and at most 1,000,000, frame/border widths at most 16 pixels, text sizes at most 512 points and each text/tooltip at most 4,096 characters. All result metadata shares its existing 1 MB limit. Live rollback restores cell graphs and table membership; clearing, deleting or replacing a table disposes its previous rendering without adding synthetic time/price points.

Native `plotarrow()` retains signed numeric signal values and all thirteen positional/named arguments through a scoped instance wrapper; the pinned engine otherwise drops positional options after the colors. Positive signals draw up arrows below their source bar, negative signals draw down arrows above it, and zero/missing values draw nothing, following the [documented sign model](https://www.tradingview.com/pine-script-docs/visuals/text-and-shapes/#plotarrow). Declared colors, offsets, source-first `show_last`, display, overlay/layer placement and custom inputs survive snapshot recalculation. Pixel heights default to 5–100; constant nonnegative integer bounds with maximum at least minimum are required. Length is `max(minheight, abs(signal) / snapshotMaxMagnitude * maxheight)`, independently per channel and before visibility/color filtering. Full-retained-snapshot normalization, omitted green/rose colors, six-pixel width and four-pixel bar gap are explicit local rendering policies; TradingView normalization and pixel calibration are unverified. Arrow values do not enter the price scale as prices. Packed histories retain lazy viewport decoding and bounded caches; translucent shafts and heads share one fill silhouette. Editable, format and precision remain metadata under current chart controls. After building, `npx playwright test e2e/pine-visuals.interaction.spec.ts --grep "native (proportional arrows|arrow custom)"` checks genuine production-worker rendering and custom-input reruns on desktop, tablet and mobile.

Native `plotbar()` renders conventional OHLC bars with a high-to-low stem, an open tick on the left and a close tick on the right. It preserves source values, dynamic colors, missing-value gaps, `show_last`, display and pane/layer placement; extrema derive from all four OHLC values. A scoped instance wrapper repairs PineTS's positional optional-argument loss using the current [twelve-argument reference](https://in.tradingview.com/pine-script-reference/v6/#fun_plotbar), including format and precision before force_overlay. The conceptual bar-plotting guide's shorter signature is stale. Omitted colors remain distinct from explicit `na`; translucent stems and ticks do not overlap. Custom inputs and large packed histories retain the existing isolation and lazy decoding. Non-color options and global invocation counts must remain constant across a snapshot; these resolved-value guards do not establish complete Pine qualifier enforcement. Editable, format and precision remain metadata under the current chart settings/formatting behavior. Bar width and defaults use qualified local pixel metrics, with visible calibration notices; full TradingView pixel equivalence is unverified. Run `npx playwright test --config=e2e/pine-bars53.config.ts` after building for the separate genuine-worker OHLC browser gate.

Constant integer `plot()` offsets move line, broken-line, step-line, circle, cross, area, broken-area, histogram and column geometry through actual chart bar slots, including visible past/future whitespace. This follows the [Pine visual offset model](https://www.tradingview.com/pine-script-docs/visuals/plots/): source values, timestamps, colors and header values remain unchanged; `show_last` filters source bars before their visual shift. Sparse chart timelines retain their real logical spacing, and autoscale uses clipped shifted geometry rather than offscreen endpoint prices. Positional and named plot settings retain custom inputs and flags after `join`; explicit `force_overlay=false` retains the script's own overlay placement. Invalid or changing offsets fail explicitly. These guards check resolved historical values, not Pine's complete type-qualifier rules. The current sixteen `plot()` arguments are supported, including named, positional and mixed `linestyle` settings. Solid, dashed and dotted styles apply to line, broken-line, step-line, step-line diamond and area outlines; other plot styles retain their ordinary rendering. Dash paths retain their phase across connected bar intervals, step corners, clipping and color changes. Area fills remain continuous; diamond steps mark retained numeric value changes. Invalid or changing resolved line styles fail explicitly. Dash/dot spacing, diamond sizes, phase origin at the first viewport neighbor and diamond transitions across missing samples use disclosed local canvas policies; TradingView pixel and corner-case parity remain unverified. After building, `npx playwright test --config=e2e/pine-linestyle86.config.ts` checks genuine production-worker pixels, custom-input reruns, gaps, offsets, layers, live rollback/confirmation and packed histories on desktop and mobile. Shape offsets retain their existing signal geometry. Referenced plot fills follow the shifted geometry described below; OHLC candle/bar functions expose no offset argument. Exact TradingView pixels and realtime execution parity are not established.

Native plot fills support independently displaced constant-integer references, including equal forward or backward offsets used by cloud indicators. The renderer joins the two boundaries on the actual shared chart logical timeline, preserves sparse source spacing and visible past/future whitespace, and clips their overlap to the pane. Source values, timestamps, custom-input IDs and packed backing remain unchanged. Each reference keeps its own `show_last` and missing-value coverage; `fillgaps` governs missing-boundary interpolation. Fill colors, gradient anchors and fill `show_last` follow the first referenced plot's source history and displacement. This source-anchor rule is a disclosed local policy, especially when the reference offsets differ; exact TradingView color timing and corner-case pixels have not been calibrated. A fill-only pane scales from its clipped painted geometry, while overlay fills retain the primary price scale. Invalid or changing reference offsets are withheld with a visible warning, including hidden references. The independent numerical/canvas checks are in `backend/tests/pine-fill-offset116.test.js`; after building, `npx playwright test --config=e2e/pine-fill-offset116.config.ts` checks genuine production-worker cloud pixels, custom-input reruns, sparse timelines and packed pan/resize/disposal on desktop and mobile.

Native circle and cross plots retain constant positive safe-integer relative sizes, including `linewidth=6`, independently of ordinary line stroke limits. Their `join=true` connectors use one-pixel strokes and clipped viewport geometry, including views entirely between numeric samples, with source-first `show_last` and real logical offsets. Cross arms share one fill path so their intersection does not compound alpha. Glyph bounds retain symbols that partly enter the pane and reserve glyph-height margins. Radius/half-arm extent of relative size plus one, one-pixel cross arms, bridging missing numeric samples, and destination-sample connector colors are local rendering policies; exact TradingView symbol pixels and gap/color behavior have not been observed. Transparent destination colors hide incoming connectors and glyphs while numeric samples can still anchor later visible connectors. Invalid/changing join flags leave symbols separate with a warning; invalid/changing relative sizes are omitted explicitly. Packed samples are decoded from viewport candidates and the numeric neighbors needed for joins; exceptionally large symbols can legitimately intersect the pane from many bars away.

Constant boolean `trackprice=true` draws a full-width square-dot pane guide, including the documented `show_last=1, offset=-99999` guide-only pattern. Guide selection uses the latest finite numeric source sample within `show_last`, independently of offsets; a transparent selected sample hides the guide without reviving an older painted color. Missing-value selection, sampled color, visible-guide autoscaling and one-pixel dot spacing are local policies, without observed TradingView edge-case or pixel parity. Numeric headers remain independent of transparency; this adds pane guides, not price-axis labels. Changing or invalid flags leave the plot body visible with a warning. Packed histories decode the selected guide once during adaptation and retain their lazy backing through redraws.

Areas use the declared color for both their solid fill to `histbase` and their outline, replacing the previous local gradient approximation. Area plots bridge missing values; broken areas retain gaps and exclude the baseline from their plotted-value scale. Histogram widths use the declared constant positive integer in pixels, defaulting to one; widths such as 12 are supported independently of the local 1–4 pixel line-width limit. Columns ignore linewidth and resize with real logical bar slots, using the pinned chart's physical-pixel gap cadence with an explicit calibration notice. Numeric filled plots require constant finite baselines, and histograms require constant widths; invalid or changing settings are omitted with a visible reason. Histogram and column baselines always contribute to scale under the documented model, including empty/offscreen channels; the all-missing TradingView corner case has not been observed. An area baseline contributes when visible numeric or clipped bridge geometry exists; empty-area scale behavior is not calibrated. Packed numeric results remain lazy through pan, zoom, resize and disposal.

Large native results use fixed transferable buffers, with at most 1,280,000 bar slots, 16,000,000 total bytes and 1,000,000 bytes of plain metadata. Values, presence/type flags and deduplicated per-bar options remain packed in the browser; timestamps bind to the requested bars. Changing numeric options use Float64 columns and presence flags within the existing three buffers per output. Constant numeric options remain in the dictionary. Requested samples reconstruct their options lazily, preserving absent, null, zero, string and boolean values. Small results retain plain point arrays only below 4,097 aggregate bar slots. Hidden references, null-valued fills, booleans, sparse points and OHLC values remain distinct. OHLC-heavy results or many numeric option columns can reach the byte limit before the channel limit. Invalid, shared, resizable, aliased or incorrectly sized buffers and invalid fill references fail explicitly. These bounds do not constitute a global memory budget for the Pine engine.

The 64-channel host capacity differs from TradingView’s [64 plot counts](https://www.tradingview.com/pine-script-docs/writing/limitations/#plot-limits), which depend on function arguments and series qualifiers. Exact TradingView count enforcement is not established. ### Native oscillator edge cases

Native Pine CCI and Williams %R show missing values when their price window has no deviation or range. MFI shows a missing value when both money-flow sums are zero, while positive-only and negative-only flow still produce 100 and 0. Missing MFI source observations leave an already complete rolling window available; startup still requires enough observations. All three helpers keep their rolling state through missing results and support provisional live updates, rollback and confirmation. The first loaded MFI observation preserves the native comparison behavior, so an initial flat warmed window can read 50 before it becomes entirely flat. The genuine engine and production chart checks compare these cases with independent formulas from TradingView's published [MFI](https://www.tradingview.com/support/solutions/43000502348-money-flow-mfi/), [CCI](https://www.tradingview.com/support/solutions/43000502001-commodity-channel-index-cci/), and [Williams %R](https://www.tradingview.com/support/solutions/43000501985-williams-r-r/) documentation. This does not claim complete TradingView language or edge-case equivalence.

Identical finite CCI windows and entirely zero MFI flow windows are recognized by exact equality, so accumulated floating-point residue cannot turn them into apparent signals. Genuine small changes and small nonzero volume are retained; no epsilon threshold is applied.
